## Q1. 신뢰 경계 (부분 답변됨)

`app/core/security.py`의 `require_member_id()`는 지금 `X-Member-Id`를 검증 없이 그대로 믿는다.
그런데도 함수로 빼고, 엔드포인트가 `Header(...)`로 직접 못 읽게 막았다.

이 함수 없이 엔드포인트 5개가 각자 헤더를 직접 받았다고 치자.
나중에 JWT 검증을 붙이는 작업은 **구체적으로 무엇을 해야 하고**, 그 작업이 **실패하는 가장 흔한 방식**은?

힌트: 실패해도 에러가 안 난다.

**8/19 답변:** "추후 확장성을 위해 막았다 / 직접 받으면 헤더 관련 문제가 게이트웨이에서 발생"

- 앞부분 ✅ — 다만 "확장성"보다 **"교체 대상을 한 곳에 고정"**이 정확하다
- 뒷부분 ❌ — 사고는 게이트웨이가 아니라 **ai-service**에서 난다. 공격자는 게이트웨이를 통과하려 하지 않고 **건너뛴다**(`:8086` 직접 호출). 게이트웨이는 자기에게 오지도 않은 요청을 막을 수 없다

> (뒷부분 재답변)

<details><summary>채점 기준</summary>

- 붙이는 작업 = JWKS로 서명 검증 + issuer 확인 + **`aud`에 `lxp-internal` 포함 확인**
- 실패 방식 = **엔드포인트 하나를 빠뜨린다.** 빠뜨려도 그 엔드포인트는 200을 잘 돌려주므로 아무 에러가 없다
- 그 결과 = 그 경로 하나로 `:8086` 직접 호출 + `X-Member-Id: 남의id`가 통과한다
- starter가 D-33에서 Java 쪽에 `common-security`로 막아둔 바로 그 구멍이다
</details>

## Q2. AI를 일부러 안 넣은 것

4단계 원칙은 "AI를 넣지 않는다"였다. `app/main.py`의 lifespan은 색인이 없으면
**경고만 남기고 서버를 띄운다.** 여기서 예외를 던지고 죽게 만들면 무엇이 나빠지나?

> 

<details><summary>채점 기준</summary>

- 서버 기동과 색인 준비가 한 덩어리가 된다
- 그러면 문제가 났을 때 **AI 쪽인지 연동 쪽인지 구분할 수 없다** — 4단계를 따로 둔 이유가 사라진다
- 나중에 Consul 헬스체크가 `/health`를 보는데, 색인 때문에 죽으면 **정상인 인스턴스가 라우팅에서 빠진다**
</details>

## Q3. 키에 기본값을 준 것 (AI-05)

`GEMINI_API_KEY`와 `LANGSMITH_API_KEY`에 기본값 `""`을 줬다. 레퍼런스는 필수 필드였다.
**필수로 두면 무엇이 깨지나?** 그리고 기본값을 준 대가로 **새로 생긴 위험**은?

> 

<details><summary>채점 기준</summary>

- 필수면 키가 없을 때 **모듈 임포트 시점**에 예외 → 서버가 아예 안 뜬다. 완료 조건 자체를 확인할 수 없다
- 새 위험 = 빈 키로도 서버가 떠서, **모델을 실제로 부르는 순간에야** 실패한다. 그래서 검사를 없앤 게 아니라 S1의 팩토리로 **옮긴** 것이다
- 검사를 옮겼다는 사실을 말해야 완전한 답이다
</details>

## Q4. 401 vs 422

FastAPI에서 `Header(...)`로 필수 선언하면 헤더 누락은 **422**가 된다.
우리는 `Header(None)`으로 받고 직접 **401**을 던진다. 왜 굳이?

> 

<details><summary>채점 기준</summary>

- 나중에 JWT 검증으로 바꾸면 그때는 **401**이 나간다
- 지금 422였다가 나중에 401이 되면 **클라이언트가 분기를 두 번 고쳐야 한다**
- 교체 전후로 밖에서 보이는 계약이 같아야 한다는 것이 요점
</details>

## Q5. pyproject의 packages 선언

```toml
[tool.hatch.build.targets.wheel]
packages = ["app"]
```

이 세 줄이 없으면 무엇이 언제 깨지나? **`uvicorn app.main:app`은 왜 그래도 도나?**

> 

<details><summary>채점 기준</summary>

- `app`이 설치 가능한 패키지로 선언되지 않는다
- `uv run python scripts/init_vectorstore.py`처럼 **파일 경로로 실행**할 때 `sys.path[0]`이 `scripts/`가 되어 `from app.core.config import ...`가 깨진다
- `uvicorn app.main:app`은 작업 디렉터리가 경로에 들어가 **우연히** 도는 것이다. 그래서 서버는 멀쩡한데 스크립트만 깨지는 형태로 나타난다
</details>
