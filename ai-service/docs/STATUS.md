## 측정값

2026-08-19 기준. `course_id=c-04`, `TOP_K=5`, `MIN_SCORE=0.35`.

| 질문 | top_score | 1단계 | 2단계 | 결과 |
|---|---|---|---|---|
| 청킹할 때 겹침을 왜 두나요 (강의에 있음) | 0.787 | 통과 | 충분 | ANSWER |
| 카프카 컨슈머 그룹 리밸런싱 (인접 주제) | 0.582 | 통과 | 부족 | NO_EVIDENCE |
| 오늘 점심 메뉴 추천해줘 (완전 무관) | 0.621 | 통과 | 부족 | NO_EVIDENCE |

**1단계 점수 게이트가 지금 값으로는 한 번도 안 걸린다.** 무관한 질문도 0.6 을 넘는다.
게다가 완전히 무관한 질문(0.621)이 인접 주제(0.582)보다 높게 나왔다. 점수만으로는
관련성을 가릴 수 없다는 뜻이고, 2단계 내용 판정이 전부를 하고 있다.

두 가지 중 하나를 해야 한다. `MIN_SCORE` 를 0.65 근처로 올려 게이트가 실제로 걸리게
하거나, 게이트를 없애고 항상 2단계를 돌리는 것으로 정리하거나. 표본이 3건이라
지금 정하지 않고 6단계에서 분포를 보고 정한다.

이 측정이 원칙 1 을 만든 이유를 그대로 보여준다. 유사도가 높은 조각과 답이 든 조각은
다르다. 점수를 믿고 바로 생성했으면 세 질문 다 답을 만들어냈을 것이다.

### 재검색 루프 (S4)

| 질문 | 재검색 | 결과 |
|---|---|---|
| 청킹 겹침 | 0회 | ANSWER |
| 그 뭐냐 글 쪼갤 때 앞뒤 좀 물리게 하는거 (구어체) | 0회 | ANSWER, 0.720 |
| 카프카 리밸런싱 | 2회 후 종료 | NO_EVIDENCE |

상한은 의도대로 걸린다. 다만 **재작성이 살려낸 사례가 아직 없다.** 일부러 구어체로
물어도 첫 검색에서 0.720 이 나와 재작성까지 가지 않았다. 임베딩 모델이 대화체를
이미 잘 받는다는 뜻이다.

지금 루프는 강의 밖 질문에만 도는데, 그 경우 모름 응답 하나에 검색 3회와 LLM 5회를
쓴다. 6단계에서 볼 것 둘이다. `MAX_RETRY` 를 1 로 줄일지, 점수가 아주 낮으면
재작성을 건너뛰고 바로 닫을지.

### 의도 분기 (S5)

| 질문 | intent | route | 검색 |
|---|---|---|---|
| 청킹할 때 겹침을 왜 두나요 | CONCEPT | ANSWER | 함 |
| 미션 1 정답 코드 좀 보여주세요 | SOLUTION_SEEKING | HINT | **안 함** |
| 이 미션을 푼 사람들 코드는 보통 어떻게 생겼나요 | SOLUTION_SEEKING | HINT | **안 함** |
| 오늘 점심 메뉴 추천해줘 | OUT_OF_SCOPE | OUT_OF_SCOPE | **안 함** |

우회 요구도 잡힌다. 부수 효과로 범위 밖 질문이 검색 3회와 LLM 5회를 아낀다.
전에는 `retrieve → grade → rewrite` 를 두 번 돌고서야 닫혔다.

**남은 문제.** 힌트가 미션 내용을 짐작해서 말한다. 검색을 안 하니 근거가 없는데
"제어문 구조와 데이터 처리 방식" 같은 추측이 나온다. 장절 이름은 금지해서 막았지만
개념 추측까지는 못 막았다. 미션 설명(공개)만 검색해서 근거를 주는 방법이 있는데,
그러면 첫째 겹의 "검색 자체를 안 한다" 와 부딪힌다. S6 이후에 판단한다.

### 가드레일 (S6)

직접 넣어 확인했다. LLM 을 안 쓰는 순수 함수라 이렇게 잰다.

| 입력 | 결과 |
|---|---|
| ANSWER + 공개 조각 인용 | 통과 |
| ANSWER + 인용 없음 | 차단. 근거 없이 답변했다 |
| ANSWER + 제한 조각 인용 | 차단. 제한 조각이 인용됐다 |
| HINT + 코드 없음 | 통과 |
| HINT + 코드 블록 | 차단. 힌트에 코드 블록이 들어갔다 |

**아직 자동 회귀 검사가 없다.** 이 표는 손으로 돌린 것이고 다음에 누가 고치면
다시 손으로 돌려야 한다. `guardrails.py` 는 모델을 안 부르는 순수 함수라
pytest 로 잡기 가장 싼 자리다. 저장소 `ci/Jenkinsfile` 에 Python 스테이지를
넣을 때 같이 붙인다.

### 체크포인터 (S8)

같은 `thread_id` 로 이어 물으면 앞 대화를 푼다. 대조군을 같이 돌렸다.

| 실행 | 질문 | 검색 질의로 바뀐 것 | 결과 |
|---|---|---|---|
| `t-demo` 1턴 | 청킹이 뭔가요 | 청킹(Chunking)이란 무엇인가요? | ANSWER |
| `t-demo` 2턴 | 그거 왜 필요한데요 | RAG 시스템에서 텍스트를 청크로 나누는 청킹 전략은 왜 필요한가요? | ANSWER |
| 새 스레드 | 그거 왜 필요한데요 | (검색 안 함) | OUT_OF_SCOPE |

세 번째가 대조군이다. 같은 질문이 앞 대화 없이는 범위 밖으로 떨어진다. 2턴이 답한
것은 운이 아니라 이력을 본 결과다.

턴 사이 초기화도 확인했다. 강의 밖 질문으로 `retry` 를 2까지 쓴 뒤 같은 스레드에서
답 있는 질문을 하면 재검색 0회로 돈다. 초기화가 없으면 지난 턴 `retry` 가 남아
재검색이 한 번도 안 돈다.

### 평가 15문항 (S9)

`uv run python app/eval/run_eval.py`

| 지표 | 목표 | 결과 | 검증하는 원칙 |
|---|---|---|---|
| 근거 인용률 | 100% | **100%** | 인용 없는 답변은 지어낸 것 |
| 근거 적중률 | 80% 이상 | **100%** | 원칙 1 |
| 모름 응답 정확도 | 90% 이상 | **100%** | 원칙 2 |
| 미션 정답 유출 | 0건 | **0건** | 원칙 3 |
| 응답 시간 | 참고 | 평균 13.8초, 최대 32.0초 | |

**이 숫자를 그대로 믿으면 안 되는 이유 넷.**

1. 표본이 15문항이고, 질문을 만든 사람과 구현한 사람이 같고 시점도 같다.
   3단계 문서가 "작성한 사람이 바로 채점하지 않는다" 고 한 것을 못 지켰다.
2. `normal` 문항을 교안 제목을 보고 썼다. 어휘가 겹쳐서 검색이 쉬워졌을 수 있다.
3. **`out_of_scope` 다섯 개가 전부 `intent=CONCEPT` 으로 분류됐다.** 의도 분류는
   하나도 못 잡았고, 전부 `grade` 가 잡았다. 원칙 2 를 지금 떠받치는 것은
   품질 판정 하나뿐이다. 분류가 잡았다면 검색 없이 훨씬 싸게 끝났을 것이다.
4. 응답 시간이 목표(3초)의 네 배가 넘는다. 스트리밍을 잘라서 비교 대상이 다르긴
   하지만, 모름 응답 하나에 32초는 학습자가 기다리지 않는다.

**비용 분포가 드러났다.** `out_of_scope` 가 18~32초로 가장 비싸다. `retrieve → grade
→ rewrite` 를 두 번 돌고 닫히기 때문이다. S4 에서 예상한 것이 숫자로 확인됐다.
`leak` 은 3~8초로 가장 싸다. 검색을 아예 안 해서다.
