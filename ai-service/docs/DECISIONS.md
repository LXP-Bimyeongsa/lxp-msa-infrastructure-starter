# 결정 기록 — ai-service

이 서비스의 결정만 남긴다. **루트 `docs/DECISIONS.md`(`D-nn`)와 번호 체계를 일부러 다르게 뒀다.**

같은 `D-nn`을 쓰면 충돌한다. 실제로 D-68은 조직 규정 QA 챗봇이 한 번 썼다가 되돌려진
번호(`revert/org-qa-chatbot-d68`)라 지금 기록상으로만 비어 있고, 그 작업이 다시 올라오면
같은 번호를 두 결정이 나눠 갖게 된다. 팀이 D-67에서 "번호를 돌려쓰면 과거 답변의 출처가
엉뚱한 곳을 가리킨다"고 정한 것과 같은 이유로 아예 겹치지 않는 접두사를 쓴다.

나중에 루트 기록으로 합치기로 하면 `AI-nn`을 그때의 빈 `D-nn`으로 옮기면 된다.
합치기 전까지 이 파일이 이 서비스의 유일한 결정 기록이다.

| 번호 | 날짜 | 결정 | 근거 | 대안 |
|---|---|---|---|---|
| AI-01 | 2026-08-19 | **AI 기능을 Python으로 만들고 이 저장소 안 `ai-service/` 폴더에 둔다.** 저장소는 분리하지 않는다 | LangGraph·LangSmith 생태계가 Python 우선이라 언어는 갈라지지만, **저장소까지 갈라지면 compose와 CI가 저장소에 없는 경로를 가리키게 된다.** D-66이 실제로 겪은 사고가 그것이다 — `compose.demo.yaml`이 저장소에 없는 디렉터리를 마운트해 컨테이너는 정상 기동하고 404만 났다. **빌드 체계가 다른 것은 CI 스테이지를 하나 더 두면 해결된다** — 저장소를 나눌 이유로는 약하다 | Spring AI — 그래프 오케스트레이션과 트레이싱을 같은 수준으로 못 씀 / 별도 저장소 — 클론한 사람이 서비스 하나를 못 받는다 |
| AI-02 | 2026-08-19 | **뼈대 단계에서 인증·Consul·compose·CI를 넣지 않는다.** 로컬 `uv run uvicorn`으로만 띄운다 | 4단계 원안대로 가면 Keycloak 연동부터 붙여야 해서 이틀 안에 설계 원칙 셋(검색 불신·모름 응답·힌트 분기)이 도는 것을 볼 수 없다. **원칙 셋을 못 보여주면 만들 이유가 없어진다** — 남는 게 단순 RAG뿐이다. 자르는 것이 아니라 순서를 미루는 것이고, 되살릴 순서를 README에 적어뒀다. **같은 저장소에 들어온 만큼 위험이 하나 늘었다** — 저장소에 있는데 CI가 한 번도 안 보는 폴더가 된다. "검사하지 않은 것은 통과한 것처럼 보인다"(D-62)가 그대로 적용된다 | 4단계 원안 전부 — 이틀 안에 안 끝남 / 인증만 먼저 — 검증할 실제 게이트웨이 토큰 흐름이 아직 없어 확인이 자체 발급 키에 그침 |
| AI-03 | 2026-08-19 | **호출자 신원을 얻는 곳을 `require_member_id()` 한 함수로 모은다.** 지금은 `X-Member-Id`를 그대로 믿고, 붙일 때 이 함수만 JWKS 검증으로 교체한다 | AI-02로 인증을 미루면 **헤더를 검증 없이 신뢰하는 코드가 남는다.** 로컬 단독이라 지금은 감수할 수 있지만, 신뢰 지점이 엔드포인트마다 흩어지면 나중에 한 곳만 빠뜨려도 뚫린다 — 그때는 사용자가 자기 토큰으로 직접 호출하며 `X-Member-Id`에 남의 id를 넣을 수 있다(D-33이 Java 쪽에서 막은 바로 그 구멍이다). 교체 대상을 한 곳으로 고정해두면 붙이는 작업이 함수 하나 수정이 된다. 헤더 누락을 422가 아니라 **401로 돌려주는 것도 같은 이유** — 교체 전후로 클라이언트가 보는 상태 코드가 같아야 한다 | 엔드포인트마다 헤더를 직접 읽기 — 교체 시 누락 지점이 생김 / 지금 당장 JWT 검증 구현 — 검증할 수단이 없고, 검증하지 않은 인증 코드는 있으나 마나 |
| AI-04 | 2026-08-19 | **뼈대에 LangChain 계열 의존성과 안 쓰는 설정 상수를 넣지 않는다** | 레퍼런스(`11_serving_ops`)는 4단계 시점에 이미 넣어뒀지만, 안 쓰는 의존성이 먼저 들어가면 무엇이 왜 필요한지가 흐려진다. `MIN_SCORE`·`TOP_K`·`MAX_RETRY`도 같은 이유로 뺐다 — 쓰는 슬라이스(S3·S4)에서 근거 주석과 함께 넣는다. 부수 효과로 `uv sync`가 chromadb 빌드를 기다리지 않는다 | 레퍼런스대로 전부 선반영 — 설정 파일만 보고는 어느 값이 실제로 동작에 영향을 주는지 알 수 없게 됨 |
| AI-05 | 2026-08-19 | **`GEMINI_API_KEY`와 `LANGSMITH_API_KEY`에 기본값을 준다** | 필수로 두면 `.env`에 키가 없을 때 **모듈 임포트 시점에 예외가 나서 서버가 아예 안 뜬다.** 뼈대 단계의 완료 조건이 "서버가 뜬다"인데 그것을 확인할 수 없게 된다. 레퍼런스 readme가 직접 지적한 함정이다. 빈 값 검사는 실제로 모델을 부르는 S1의 팩토리에서 한다 — 검사를 없앤 게 아니라 필요한 자리로 옮겼다 | 필수 필드 유지 — 트레이싱을 안 쓰는 환경에서도 키를 넣어야 함 |
| AI-06 | 2026-08-19 | **초기 교안 원본으로 potenup 학습 자료 마크다운을 쓴다** | 3단계가 요구하는 조각 300개 이상을 지금 확보할 수 있는 유일한 실물이다. 실제 LXP 강의 교안이 오면 같은 규약으로 갈아끼운다. **미션 해설(restricted) 역할을 할 파일을 함께 만들어야 한다** — 제한 조각이 하나도 없으면 원칙 3이 동작하는지 확인할 방법 자체가 없다 | 샘플 교안 신규 작성 — 통제는 쉽지만 작성에 시간이 들고 분량이 안 나옴 / 데이터 없이 진행 — S1이 시작되지 않음 |
| AI-07 | 2026-08-19 | **저장소 루트 파일을 건드리지 않는다.** 이 서비스 관련 변경은 전부 `ai-service/` 안에서만 한다 | 루트 `AGENTS.md`가 파일 수정에 사용자 승인을 요구한다. 그리고 뼈대 단계에서 루트를 고쳐봐야 붙이지도 않을 compose·CI 설정만 늘어난다. **대신 미룬 것을 README에 적어둔다** — 적어두지 않으면 "안 한 것"과 "잊은 것"이 구분되지 않는다 | 지금 루트까지 정리 — 승인 절차를 건너뛰고, 아직 쓰지 않을 설정이 먼저 들어간다 |
