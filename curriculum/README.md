# 커리큘럼 로드맵

학습자가 목표와 기간, 현재 수준을 넣으면 기존 강의 중에서 골라 학습 순서를 짜주는 기능이다.

## 폴더

```
curriculum/
  roadmap/              코어 패키지. CLI·평가·서비스가 전부 이걸 쓴다
    catalog.py          강의 로드          <- course-service API 로 바꿀 때 여기
    prompt.py           프롬프트 조립
    verify.py           코드 검증 4가지
    schedule.py         주차 배분
    llm.py              모델 호출          <- 모델을 바꿀 때 여기
    engine.py           생성 -> 검증 -> 재생성 루프
  service/              FastAPI. HTTP 경계만 담당한다
    app.py
    Dockerfile
    requirements.txt
  scripts/              CLI 와 평가 러너
  data/courses.json     강의 카탈로그 43개
```

`scripts/` 와 `README.md` 는 이미지에 넣지 않는다. 런타임에 필요 없다.

## 강의 카탈로그

로드맵은 영상을 건드리지 않는다. 메타데이터만 읽어 순서를 배열한다. 그래서 전부
`videoUploaded: false` 이고 영상 파일이 없다.

```json
{
  "title": "스프링 트랜잭션의 이해",
  "description": "선언적 트랜잭션, 전파 속성, 프록시가 만드는 함정을 짚는다.",
  "instructorId": 2,
  "estimatedHours": 8,
  "level": "INTERMEDIATE",
  "topics": ["백엔드", "스프링", "트랜잭션"],
  "videoUploaded": false
}
```

| 필드 | 로드맵에서 쓰는 곳 |
|---|---|
| `title`·`description` | 어떤 강의인지 모델이 판단하는 근거 |
| `estimatedHours` | **기간 검증.** 합계가 목표 기간을 넘으면 재생성 |
| `track` | **순서 검증 단위.** 같은 트랙 안에서만 난이도 단조성을 본다 |
| `level` | **전역 난이도 1~5.** 입력받은 수준과 매칭 |
| `topics` | 주제 태그. 목표와의 관련성 판단 |

### 난이도는 전역 척도다

```
L1  완전 입문   프로그래밍이나 해당 분야를 처음 접함
L2  기초        언어와 도구의 기본기
L3  중급        프레임워크와 실무 도구, 설계 진입
L4  중상급      심화 개념, 최적화, 운영
L5  고급        아키텍처, 대규모, 동시성
```

**트랙 안에서만 의미를 갖게 두면 안 된다.** `스프링 프레임워크 입문`을 "스프링
기준 입문"이라고 L1 으로 두면, 검증기가 `자바 객체지향 설계`(L2)보다 앞에 와야
한다고 판정한다. 실제로는 자바를 먼저 배우고 스프링으로 가야 하는데도 그렇다.

전역 척도로 두면 트랙을 넘어 그대로 비교할 수 있다. `스프링 프레임워크 입문`은
L3 이다.

### 현황

```
강의 43개 · 총 762시간
BEGINNER 16 · INTERMEDIATE 19 · ADVANCED 8
```

주요 트랙은 백엔드 15, 프론트엔드 8, 인프라 7, 데이터베이스 7이다.

### 설계할 때 챙긴 것

**난이도에 계단이 지게 배치했다.** 같은 트랙 안에서 입문에서 고급으로 이어진다.
이게 없으면 순서 배열이 무의미해진다.

```
자바 프로그래밍 입문 (입문 40h)
  → 자바 객체지향 설계 (중급 25h)
    → 스프링 프레임워크 입문 (입문 30h)
      → 스프링 데이터 JPA (중급 20h)
        → JPA 성능 튜닝 (고급 12h)
```

**기간 검증이 실제로 걸리도록 총량을 잡았다.** 백엔드 트랙만 208시간이라
주 20시간으로 3개월(260시간)이면 빠듯하고 6개월(520시간)이면 여유가 있다.
그래야 "기간 초과 → 범위 조정 후 재생성" 루프가 실제로 돈다.

**태그를 여러 개 붙였다.** `스프링 데이터 JPA` 는 백엔드이면서 데이터베이스이기도 하다.
목표에 따라 다른 트랙으로 묶일 수 있어야 한다.

**제목을 실제 있을 법한 것으로 썼다.** "강의1, 강의2" 로 채우면 로드맵 결과가
껍데기로 보인다.

## 적재

```bash
./curriculum/scripts/seed.sh
```

기존 강의를 지우고 다시 넣는다. 카탈로그를 고쳐가며 여러 번 돌릴 수 있다.

`mongo-init` 잡에 넣지 않은 이유는 그쪽이 최초 기동에만 실행되기 때문이다(D-29).
다시 넣으려면 볼륨을 지워야 해서 개발 중에 불편하다.

## 1단계 스크립트

카탈로그를 통째로 프롬프트에 넣고 LLM 에게 경로를 짜게 한 뒤 결과를 코드로 검증한다.
서비스도 LangGraph 도 아직 없다. 되는지부터 본다.

```bash
export GEMINI_API_KEY=...
python curriculum/scripts/roadmap.py --goal "백엔드 개발자가 되고 싶다" --weeks 26
python curriculum/scripts/roadmap.py --goal "프론트엔드로 취업" --weeks 8 --hours-per-week 15 --level 2
```

의존성이 없다. 표준 라이브러리만 쓴다.

### 역할을 나눈 기준

```
LLM   어떤 강의를 어떤 순서로 들을지 고른다
코드  존재하는 강의인지, 기간에 맞는지, 순서가 뒤집혔는지 검증한다
      주차 배분도 코드가 한다
```

주차 배분을 LLM 에게 맡기지 않는다. 시간 합산이라 계산이지 판단이 아니다.

### 검증 4가지

`verify()` 가 본다. 나중에 평가 하네스의 씨앗이 된다.

| 검증 | 잡는 것 |
|---|---|
| 번호 범위 | 목록에 없는 강의를 지어냈나 |
| 중복 | 같은 강의를 여러 번 골랐나 |
| 기간 | 시간 합이 예산을 넘나 |
| 난이도 역전 | 같은 트랙에서 높은 레벨이 낮은 레벨보다 앞인가 |

문제가 있으면 종료 코드 2 로 끝난다. CI 에 걸 수 있다.

### 주차 배분은 강의를 쪼갠다

40시간짜리를 주 20시간으로 들으면 두 주가 걸린다. 강의를 통째로 한 주에 몰아넣으면
그 주가 40시간이 되고 주차 수도 예산을 넘긴다.

쪼개면 총 주차가 `ceil(총시간 / 주당시간)` 으로 떨어진다. **총시간이 예산 안이면
주차도 자동으로 예산 안**이라 주차를 따로 검증할 필요가 없다.

### 재시도

무료 티어에서 429(한도)와 503(과부하)을 실제로 만난다. 지수 백오프로 2·4·8초를
기다리며 최대 3회 재시도한다. 네트워크 오류도 같이 잡는다.

### 실측

```
프롬프트 2,618자 · 입력 1,564 토큰 · 출력 1,277 토큰
```

TPM 250,000 기준 분당 90건 이상 가능하다. 무료 티어에서 부담이 없다.

`description` 은 프롬프트에서 뺐다. 순서를 짜는 데 필요 없고 토큰만 늘린다.

## 평가셋

`data/eval_roadmap.json` 에 케이스를 적어두고 `scripts/evaluate.py` 로 전부 돌린다.
프롬프트를 고칠 때마다 나아졌는지 숫자로 확인한다. 감으로 고치면 뭐가 좋아졌는지
알 수 없다.

```bash
export GEMINI_API_KEY=...
python curriculum/scripts/evaluate.py
python curriculum/scripts/evaluate.py --case R-04 --verbose
```

### 채점은 두 층이다

```
공통  roadmap.verify() 4가지    번호 범위 · 중복 · 기간 · 트랙 내 난이도 역전
개별  케이스마다 적어둔 기대     아래 표
```

| 기대 | 잡는 것 |
|---|---|
| `tracks` + `trackRatioMin` | 목표와 다른 트랙으로 새는가 |
| `mustInclude` | 빠지면 안 되는 강의가 빠졌나 |
| `mustExclude` | 들어가면 안 되는 강의가 들어왔나 |
| `minLevel` | 수준을 무시하고 너무 쉬운 것을 주는가 |
| `fillRateMin` | 고를 수 있는 만큼 골랐는가 |
| `maxSelected` | 채울 수 없는 목표에 억지로 채우는가 |
| `minSelected` | 고를 게 있는데 손을 놓았는가 |

### 채움은 예산이 아니라 가용 대비로 잰다

```
usage = 선택 시간 / min(예산, 기대 트랙의 가용 시간)
```

**예산 대비로 재면 안 된다.** 카탈로그가 그 트랙에 그만큼 없으면 "예산을 채워라"가
곧 "관계없는 강의를 넣어라"가 된다.

R-06 이 그랬다. 예산 120시간인데 데이터베이스 트랙에서 수준에 맞는 강의가 62시간
어치뿐이었다. 32시간만 고른 모델이 맞았고 27% 로 실패 판정한 지표가 틀렸다.

**전부 코드로 잰다.** 사람이 읽고 판단하는 항목은 넣지 않았다. 자동으로 안 돌면
프롬프트를 고칠 때마다 안 쓰게 되고, 그러면 있으나 마나다.

### 케이스 구성

| id | 보는 것 |
|---|---|
| R-01 | 기본. 백엔드 풀코스 |
| R-02 | 다른 트랙. 프론트엔드가 백엔드로 새지 않는지 |
| R-03 | 주당 시간이 적은 경우 |
| R-04 | **수준 반영.** 자바를 아는 사람에게 L1 을 다시 주는가 |
| R-05 | **예산 압박.** 40시간으로 백엔드 개발자는 불가능하다 |
| R-06 | 심화 단일 트랙 |
| R-07 | 목표가 넓은 경우 |
| R-08 | **함정.** 카탈로그로 채울 수 없는 목표에 억지로 채우는가 |

R-08 이 규정 챗봇의 함정 질문과 같은 역할이다. "요리사가 되고 싶다" 에 강의를
잔뜩 골라주면 안 된다.

실패하면 종료 코드 2 로 끝난다. CI 에 걸 수 있다.

케이스 수만큼 API 를 호출한다. 무료 티어 RPM 을 넘지 않게 사이에 쉰다(`--sleep`).

## 무료 티어 한도

실제 에러가 알려준 값이다. 문서나 블로그 수치를 믿지 말고 이걸 기준으로 삼는다.

```
quotaId : GenerateRequestsPerDayPerProjectPerModel-FreeTier
limit   : 20
```

**하루 20건이다.** 프로젝트와 모델 단위로 센다.

모델 단위라 다른 모델로 바꾸면 별도 쿼터를 쓴다. 평가 8건을 두 번 돌리면 한 모델
몫이 끝나므로, 개발 중에는 모델을 바꿔가며 돌거나 유료로 전환해야 한다.

```bash
python curriculum/scripts/evaluate.py --model gemini-3.5-flash-lite
```

실사용에서도 문제가 된다. 훈련생 10명이 하루 2건씩만 물어봐도 한도다.
**로드맵을 실제로 쓰려면 유료 전환이 필요하다.**

## 프롬프트를 고친 기록

평가셋이 잡아낸 것과 고친 내용이다. 같은 문제가 다시 나오면 여기를 먼저 본다.

### 예산 채우기가 목표 적합성을 이기던 것

R-05("백엔드 개발자", 40시간 예산)에서 백엔드 강의를 **하나도** 고르지 않고
데이터베이스·인프라·협업에서 짧은 것 3개로 예산을 채웠다. R-08("요리사가 되고
싶다")에서는 관련 강의가 없는데도 10개 236시간을 채웠다.

규칙을 나열하는 대신 **절차와 우선순위**로 바꿨다.

```
[따를 순서]      목표 트랙을 먼저 정하고 → 수준부터 난이도 순으로 → 남으면 인접 트랙 → 그래도 남으면 남긴다
[우선순위]       목표 적합성 > 난이도 순서 > 예산 활용
[빈 배열]        카탈로그로 채울 수 없는 목표면 selected 를 빈 배열로 둔다
```

결과: R-08 이 0개로 통과. R-05 의 트랙 비율이 0% → 100%. R-01 트랙 비율 70% → 82%.

### 예산이 유연한 것으로 읽히던 것

위 우선순위가 너무 세게 먹혀서 이번에는 예산을 넘겼다. 예산 상한을 우선순위 위로
빼서 절대 제약으로 명시했다.

```
[절대 지켜야 하는 것]  합계는 예산을 절대 넘지 않는다. 넘을 것 같으면 뒤쪽을 뺀다.
[그다음 우선순위]      목표 적합성 > 난이도 순서 > 예산 활용
```

### 프롬프트로 안 잡히는 것

R-05 는 세 번 조여도 40시간 예산에 65시간을 고른다. `자바 프로그래밍 입문`(40h)
하나로 예산이 딱 차는데 `자바 객체지향 설계`(25h)를 얹는다.

**산술 제약은 프롬프트로 보장되지 않는다.** 검증에서 잡아 재생성하는 편이 확실하다.

## 재생성 루프

```
경로 생성 → 검증
              ├ 통과 → 끝
              └ 실패 → 문제를 프롬프트에 붙여 재생성 (기본 최대 2회)
```

재생성 프롬프트에 검증이 잡은 것을 그대로 돌려준다.

```
[직전 시도의 문제]
직전 선택: 자바 프로그래밍 입문(40h), 자바 객체지향 설계(25h)
합계 65h / 예산 40h

문제:
  - 기간 초과: 65h > 40h

25시간을 줄여야 한다. 목표에서 먼 강의부터 뺀다. 강의 하나만 남아도 괜찮다.
목표 적합성은 유지한다. 관계없는 강의로 바꿔치지 않는다.
```

"강의 하나만 남아도 괜찮다"가 주효했다. 모델이 하나만 고르는 것을 어색해했다.

**루프는 `verify()` 가 잡는 4가지만 재시도한다.** 채움 부족이나 트랙 비율 미달 같은
케이스별 기대는 루프가 보지 않는다. 그건 프롬프트로 잡아야 한다.

`--max-attempts 1` 로 주면 루프 없이 순수 프롬프트 성능만 잰다.

### 첫 시도 통과율

```
7/8 통과 · 첫 시도 통과 7/8 · 호출 9회
```

루프가 있으면 결국 통과하지만 호출이 늘면 쿼터와 지연을 먹는다. **첫 시도 통과율이
프롬프트 품질 지표다.** 이 숫자를 올리는 것이 프롬프트 최적화의 목표다.

### 최근 실행

```
R-01  통과   22개 · 398h/520h · 트랙  86% · 채움  88%
R-02  통과    7개 · 158h/240h · 트랙 100% · 채움  66%
R-03  통과    6개 · 108h/240h · 트랙 100% · 채움  53%
R-04  통과    8개 · 138h/200h · 트랙 100% · 채움  69%
R-05  통과    1개 ·  40h/ 40h · 트랙 100% · 채움 100% · 재생성 1회
R-06  통과    3개 ·  32h/120h · 트랙 100% · 채움  52%
R-07  통과   15개 · 313h/520h ·             채움  60%
```

## 서비스

```bash
docker compose -f compose.curriculum.yaml up -d --build
```

`compose.yaml` 이 먼저 떠 있어야 한다. 네트워크(`lxp-net`)를 새로 만들지 않고 붙는다.
API 키는 루트 `.env` 의 `GEMINI_API_KEY` 를 읽는다. 없으면 기동은 되고
로드맵 호출에서 503 이 난다.

| | |
|---|---|
| `GET /actuator/health` | compose healthcheck 와 Prometheus 스크레이프 |
| `GET /api/ai/curriculum/catalog` | 고를 수 있는 강의 목록 |
| `POST /api/ai/curriculum/roadmap` | 로드맵 생성 |

```bash
curl -s localhost:8086/api/ai/curriculum/roadmap \
  -H 'Content-Type: application/json' \
  -d '{"goal":"백엔드 개발자가 되고 싶다","weeks":8,"hoursPerWeek":15,"level":1}'
```

### 별도 compose 파일인 이유

`compose.yaml` 은 인프라와 도메인 서비스 자리다. AI 기능은 아직 붙였다 뗐다 하는
단계라 평소 개발에서까지 떠 있을 이유가 없다. `compose.demo.yaml` 과 같은 판단이고
D-14 의 용도별 분리를 따른다.

### 지금 안 하는 것

Consul 에 등록하지 않는다. 파이썬이라 Spring Cloud Consul 이 없고, gateway 라우팅
전이라 포트로 직접 부른다. DB 도 쓰지 않는다. 강의 목록은 이미지 안 JSON 을
기동할 때 한 번 읽는다. `course-service` 목록 API 로 바꾸면 그때 `depends_on` 이 생긴다.

### 상태 코드

429 는 그대로 429 로 내려보낸다. 무료 티어 하루 20건 한도라 서버 잘못이 아니라
잠시 뒤 다시 부르면 되는 것이다. 화면에서 재시도를 안내할 수 있어야 해서
502 로 뭉개지 않았다. 나머지 모델 오류는 502 다.

## 결정 기록을 여기 두는 이유

이 폴더는 자기완결로 유지한다. 기존 폴더를 건드리지 않으려고 `docs/DECISIONS.md`에
항목을 넣지 않았다. 카탈로그 설계 근거는 위 절에 적어뒀다.

로드맵이 실제로 붙어 저장소 구조에 영향을 주게 되면 그때 `docs/DECISIONS.md`에
항목을 추가하는 것이 맞다.

## 아직 남은 것

**`Course` 엔티티에 필드가 없다.** MongoDB 는 스키마가 없어서 적재는 되지만,
`course-service` 의 자바 엔티티가 `estimatedHours`·`level`·`topics` 를 모른다.
읽으려면 엔티티에 필드를 추가해야 한다.

**강의 목록 조회 API 가 없다.** 지금은 단건 조회(`GET /api/courses/{id}`)만 있다.
로드맵은 전체 목록이 필요하다.

둘 다 `course-service` 를 건드리는 일이라 담당자와 협의가 필요하다.
