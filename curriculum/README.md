# 커리큘럼 로드맵

학습자가 목표와 기간, 현재 수준을 넣으면 기존 강의 중에서 골라 학습 순서를 짜주는 기능이다.

## 폴더

```
curriculum/
  data/courses.json     강의 카탈로그 43개
  scripts/seed.sh       MongoDB course_db 에 적재
```

## 강의 카탈로그

로드맵은 영상을 건드리지 않는다. 메타데이터만 읽어 순서를 배열한다. 그래서 전부
`videoUploaded: false` 이고 영상 파일이 없다.

```json
{
  "title": "스프링 트랜잭션의 이해",
  "description": "선언적 트랜잭션, 전파 속성, 프록시가 만드는 함정을 짚는다.",
  "instructorId": 2,
  "estimatedHours": 8,
  "level": "INTERMEDIATE",
  "topics": ["백엔드", "스프링", "트랜잭션"],
  "videoUploaded": false
}
```

| 필드 | 로드맵에서 쓰는 곳 |
|---|---|
| `title`·`description` | 어떤 강의인지 모델이 판단하는 근거 |
| `estimatedHours` | **기간 검증.** 합계가 목표 기간을 넘으면 재생성 |
| `level` | 입력받은 수준과 매칭 |
| `topics` | 순서 배열의 근거. 같은 트랙을 이어 붙인다 |

### 현황

```
강의 43개 · 총 762시간
BEGINNER 16 · INTERMEDIATE 19 · ADVANCED 8
```

주요 트랙은 백엔드 15, 프론트엔드 8, 인프라 7, 데이터베이스 7이다.

### 설계할 때 챙긴 것

**난이도에 계단이 지게 배치했다.** 같은 트랙 안에서 입문에서 고급으로 이어진다.
이게 없으면 순서 배열이 무의미해진다.

```
자바 프로그래밍 입문 (입문 40h)
  → 자바 객체지향 설계 (중급 25h)
    → 스프링 프레임워크 입문 (입문 30h)
      → 스프링 데이터 JPA (중급 20h)
        → JPA 성능 튜닝 (고급 12h)
```

**기간 검증이 실제로 걸리도록 총량을 잡았다.** 백엔드 트랙만 208시간이라
주 20시간으로 3개월(260시간)이면 빠듯하고 6개월(520시간)이면 여유가 있다.
그래야 "기간 초과 → 범위 조정 후 재생성" 루프가 실제로 돈다.

**태그를 여러 개 붙였다.** `스프링 데이터 JPA` 는 백엔드이면서 데이터베이스이기도 하다.
목표에 따라 다른 트랙으로 묶일 수 있어야 한다.

**제목을 실제 있을 법한 것으로 썼다.** "강의1, 강의2" 로 채우면 로드맵 결과가
껍데기로 보인다.

## 적재

```bash
./curriculum/scripts/seed.sh
```

기존 강의를 지우고 다시 넣는다. 카탈로그를 고쳐가며 여러 번 돌릴 수 있다.

`mongo-init` 잡에 넣지 않은 이유는 그쪽이 최초 기동에만 실행되기 때문이다(D-29).
다시 넣으려면 볼륨을 지워야 해서 개발 중에 불편하다.

## 결정 기록을 여기 두는 이유

이 폴더는 자기완결로 유지한다. 기존 폴더를 건드리지 않으려고 `docs/DECISIONS.md`에
항목을 넣지 않았다. 카탈로그 설계 근거는 위 절에 적어뒀다.

로드맵이 실제로 붙어 저장소 구조에 영향을 주게 되면 그때 `docs/DECISIONS.md`에
항목을 추가하는 것이 맞다.

## 아직 남은 것

**`Course` 엔티티에 필드가 없다.** MongoDB 는 스키마가 없어서 적재는 되지만,
`course-service` 의 자바 엔티티가 `estimatedHours`·`level`·`topics` 를 모른다.
읽으려면 엔티티에 필드를 추가해야 한다.

**강의 목록 조회 API 가 없다.** 지금은 단건 조회(`GET /api/courses/{id}`)만 있다.
로드맵은 전체 목록이 필요하다.

둘 다 `course-service` 를 건드리는 일이라 담당자와 협의가 필요하다.
