# 커리큘럼 로드맵

학습자가 목표와 기간, 현재 수준을 넣으면 기존 강의 중에서 골라 학습 순서를 짜주는 기능이다.

## 폴더

```
curriculum/
  data/courses.json     강의 카탈로그 43개
  scripts/seed.sh       MongoDB course_db 에 적재
```

## 강의 카탈로그

로드맵은 영상을 건드리지 않는다. 메타데이터만 읽어 순서를 배열한다. 그래서 전부
`videoUploaded: false` 이고 영상 파일이 없다.

```json
{
  "title": "스프링 트랜잭션의 이해",
  "description": "선언적 트랜잭션, 전파 속성, 프록시가 만드는 함정을 짚는다.",
  "instructorId": 2,
  "estimatedHours": 8,
  "level": "INTERMEDIATE",
  "topics": ["백엔드", "스프링", "트랜잭션"],
  "videoUploaded": false
}
```

| 필드 | 로드맵에서 쓰는 곳 |
|---|---|
| `title`·`description` | 어떤 강의인지 모델이 판단하는 근거 |
| `estimatedHours` | **기간 검증.** 합계가 목표 기간을 넘으면 재생성 |
| `track` | **순서 검증 단위.** 같은 트랙 안에서만 난이도 단조성을 본다 |
| `level` | **전역 난이도 1~5.** 입력받은 수준과 매칭 |
| `topics` | 주제 태그. 목표와의 관련성 판단 |

### 난이도는 전역 척도다

```
L1  완전 입문   프로그래밍이나 해당 분야를 처음 접함
L2  기초        언어와 도구의 기본기
L3  중급        프레임워크와 실무 도구, 설계 진입
L4  중상급      심화 개념, 최적화, 운영
L5  고급        아키텍처, 대규모, 동시성
```

**트랙 안에서만 의미를 갖게 두면 안 된다.** `스프링 프레임워크 입문`을 "스프링
기준 입문"이라고 L1 으로 두면, 검증기가 `자바 객체지향 설계`(L2)보다 앞에 와야
한다고 판정한다. 실제로는 자바를 먼저 배우고 스프링으로 가야 하는데도 그렇다.

전역 척도로 두면 트랙을 넘어 그대로 비교할 수 있다. `스프링 프레임워크 입문`은
L3 이다.

### 현황

```
강의 43개 · 총 762시간
BEGINNER 16 · INTERMEDIATE 19 · ADVANCED 8
```

주요 트랙은 백엔드 15, 프론트엔드 8, 인프라 7, 데이터베이스 7이다.

### 설계할 때 챙긴 것

**난이도에 계단이 지게 배치했다.** 같은 트랙 안에서 입문에서 고급으로 이어진다.
이게 없으면 순서 배열이 무의미해진다.

```
자바 프로그래밍 입문 (입문 40h)
  → 자바 객체지향 설계 (중급 25h)
    → 스프링 프레임워크 입문 (입문 30h)
      → 스프링 데이터 JPA (중급 20h)
        → JPA 성능 튜닝 (고급 12h)
```

**기간 검증이 실제로 걸리도록 총량을 잡았다.** 백엔드 트랙만 208시간이라
주 20시간으로 3개월(260시간)이면 빠듯하고 6개월(520시간)이면 여유가 있다.
그래야 "기간 초과 → 범위 조정 후 재생성" 루프가 실제로 돈다.

**태그를 여러 개 붙였다.** `스프링 데이터 JPA` 는 백엔드이면서 데이터베이스이기도 하다.
목표에 따라 다른 트랙으로 묶일 수 있어야 한다.

**제목을 실제 있을 법한 것으로 썼다.** "강의1, 강의2" 로 채우면 로드맵 결과가
껍데기로 보인다.

## 적재

```bash
./curriculum/scripts/seed.sh
```

기존 강의를 지우고 다시 넣는다. 카탈로그를 고쳐가며 여러 번 돌릴 수 있다.

`mongo-init` 잡에 넣지 않은 이유는 그쪽이 최초 기동에만 실행되기 때문이다(D-29).
다시 넣으려면 볼륨을 지워야 해서 개발 중에 불편하다.

## 1단계 스크립트

카탈로그를 통째로 프롬프트에 넣고 LLM 에게 경로를 짜게 한 뒤 결과를 코드로 검증한다.
서비스도 LangGraph 도 아직 없다. 되는지부터 본다.

```bash
export GEMINI_API_KEY=...
python curriculum/scripts/roadmap.py --goal "백엔드 개발자가 되고 싶다" --weeks 26
python curriculum/scripts/roadmap.py --goal "프론트엔드로 취업" --weeks 8 --hours-per-week 15 --level 2
```

의존성이 없다. 표준 라이브러리만 쓴다.

### 역할을 나눈 기준

```
LLM   어떤 강의를 어떤 순서로 들을지 고른다
코드  존재하는 강의인지, 기간에 맞는지, 순서가 뒤집혔는지 검증한다
      주차 배분도 코드가 한다
```

주차 배분을 LLM 에게 맡기지 않는다. 시간 합산이라 계산이지 판단이 아니다.

### 검증 4가지

`verify()` 가 본다. 나중에 평가 하네스의 씨앗이 된다.

| 검증 | 잡는 것 |
|---|---|
| 번호 범위 | 목록에 없는 강의를 지어냈나 |
| 중복 | 같은 강의를 여러 번 골랐나 |
| 기간 | 시간 합이 예산을 넘나 |
| 난이도 역전 | 같은 트랙에서 높은 레벨이 낮은 레벨보다 앞인가 |

문제가 있으면 종료 코드 2 로 끝난다. CI 에 걸 수 있다.

### 주차 배분은 강의를 쪼갠다

40시간짜리를 주 20시간으로 들으면 두 주가 걸린다. 강의를 통째로 한 주에 몰아넣으면
그 주가 40시간이 되고 주차 수도 예산을 넘긴다.

쪼개면 총 주차가 `ceil(총시간 / 주당시간)` 으로 떨어진다. **총시간이 예산 안이면
주차도 자동으로 예산 안**이라 주차를 따로 검증할 필요가 없다.

### 재시도

무료 티어에서 429(한도)와 503(과부하)을 실제로 만난다. 지수 백오프로 2·4·8초를
기다리며 최대 3회 재시도한다. 네트워크 오류도 같이 잡는다.

### 실측

```
프롬프트 2,618자 · 입력 1,564 토큰 · 출력 1,277 토큰
```

TPM 250,000 기준 분당 90건 이상 가능하다. 무료 티어에서 부담이 없다.

`description` 은 프롬프트에서 뺐다. 순서를 짜는 데 필요 없고 토큰만 늘린다.

## 결정 기록을 여기 두는 이유

이 폴더는 자기완결로 유지한다. 기존 폴더를 건드리지 않으려고 `docs/DECISIONS.md`에
항목을 넣지 않았다. 카탈로그 설계 근거는 위 절에 적어뒀다.

로드맵이 실제로 붙어 저장소 구조에 영향을 주게 되면 그때 `docs/DECISIONS.md`에
항목을 추가하는 것이 맞다.

## 아직 남은 것

**`Course` 엔티티에 필드가 없다.** MongoDB 는 스키마가 없어서 적재는 되지만,
`course-service` 의 자바 엔티티가 `estimatedHours`·`level`·`topics` 를 모른다.
읽으려면 엔티티에 필드를 추가해야 한다.

**강의 목록 조회 API 가 없다.** 지금은 단건 조회(`GET /api/courses/{id}`)만 있다.
로드맵은 전체 목록이 필요하다.

둘 다 `course-service` 를 건드리는 일이라 담당자와 협의가 필요하다.
