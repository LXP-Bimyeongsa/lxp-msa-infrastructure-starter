## 1. 왜 AI를 썼나

### 데이터가 먼저 결정했다

기능을 고르기 전에 **쓸 수 있는 데이터가 뭔지** 봤다.

| 있는 것 | 없는 것 |
|---|---|
| 강의 제목 | 강의 영상 (**43개 중 0개**) |
| 한 줄 설명 (평균 31자) | 자막·대본 |
| 시간·트랙·난이도·태그 | 수강 이력, 질문 기록 |

**전체 강의 설명을 다 합쳐도 1,363자다.** A4 한 장이 안 된다.

이 숫자가 선택지를 잘라냈다.

```
강의 내용 Q&A 챗봇     불가.   답할 내용이 없다
영상 요약·자막 추출     불가.   영상이 0개
내용 기반 추천          불가.   1,363자로는 유사도가 의미 없다
RAG                    불필요.  1,363자면 그냥 통째로 넣으면 된다
```

**RAG를 안 쓴 게 게을러서가 아니라, 검색할 만큼의 문서가 없어서다.**

### 그래서 남은 것

메타데이터만으로 되는 일이 뭔가. **고르고 순서를 정하는 일**이다.

```
입력   "백엔드 개발자가 되고 싶다" · 8주 · 주 15시간 · 완전 입문
출력   43개 중 5개 선택 · 118시간 · 8주치 주차별 배분
```

내용을 이해할 필요가 없다. **제목·트랙·난이도·시간만으로 판단이 선다.**

### 규칙 기반으로는 왜 안 되나

`if 목표 == "백엔드": 백엔드 트랙 전부` 로 하면 될 것 같지만 두 군데서 막힌다.

**첫째, 목표가 자유 문장이다.**

```
"백엔드 개발자가 되고 싶다"           → 백엔드
"자바는 아는데 스프링으로 실무를"       → 백엔드, 단 입문은 건너뛰고
"서버 배포까지 혼자 하고 싶다"         → 백엔드 + 인프라
"데이터베이스 성능 튜닝을 제대로"       → 데이터베이스, 중급 이상만
```

이걸 규칙으로 나열하면 끝이 없다. **문장을 트랙과 수준으로 옮기는 것**이 언어 이해다.

**둘째, 조합을 정해야 한다.** 예산 안에서 뭘 넣고 뭘 뺄지, 트랙이 여럿이면 어떤 비중으로 섞을지는
정답이 하나가 아니다. 사람이 짜던 판단이다.

### 대신 AI를 안 쓴 부분이 있다

**계산으로 답이 나오는 것은 코드가 한다.**

| | 맡는 것 |
|---|---|
| LLM | 무엇을 고를지, 어떤 순서일지 |
| 코드 | 존재하나 · 겹치나 · 예산을 넘나 · 난이도가 역순인가 · 주차 배분 |

"40 + 25가 65인가"를 모델에게 묻지 않는다. **판정이 흔들리고 토큰만 쓴다.**

이 구분이 다음 두 절의 전제다.

## 2. 무료 API를 어떻게 갈아끼우나

### 교체 지점이 한 곳이다

`roadmap/llm.py` 하나. 나머지 코드는 이 모양에만 의존한다.

```python
generate(prompt, deadline) -> (파싱된 JSON, 사용 토큰)
```

호출은 표준 라이브러리 `urllib` 로 직접 한다. SDK를 안 쓴다.

### 세 단계로 갈린다

| 바꾸는 것 | 드는 일 |
|---|---|
| 무료 → 유료 | **코드 0줄.** 환경변수 `GEMINI_API_KEY` 만 |
| 다른 모델 | **코드 0줄.** `GEMINI_MODEL` 환경변수 |
| 다른 공급자 (OpenAI·Anthropic·로컬) | 클래스 하나 (60줄쯤) |

```bash
GEMINI_MODEL=gemini-3.6-flash docker compose -f compose.curriculum.yaml up -d
```

**나머지 파일은 안 건드린다** — `prompt.py`, `verify.py`, `schedule.py`, `engine.py`, `app.py`.

### 무료 티어를 실제로 재봤다

블로그마다 하루 250건, 1500건이라고 쓰여 있는데 **틀린 값이다.** 실제 오류 응답에 이렇게 찍힌다.

```json
{ "quotaId": "GenerateRequestsPerDayPerProjectPerModel-FreeTier",
  "quotaValue": "20" }
```

**하루 20건이다. 그리고 프로젝트당이 아니라 "프로젝트 × 모델"당이다.**

이게 실용적으로 중요하다. 다 쓰면 **모델 이름만 바꿔도 20건이 새로 생긴다.** 시연 중에 한도에
걸려도 환경변수 하나로 복구된다.

### 모델을 갈아끼우는 것은 정석이 아니다

모델 고정이 정석이다. 모델이 바뀌면 같은 입력에도 결과가 달라진다.
그런데 무료 한도가 프로젝트 x 모델당 하루 20건이라 한 모델로는 개발과 시연을 못 버틴다.
그래서 고정 대신 교체를 골랐다. 코드가 아니라 .env 한 줄만 바꾼다.
대신 어느 모델이 답했는지를 health, 응답, 지표, 화면에 남긴다.
유료로 가면 교체를 그만두고 한 모델로 고정한다.

```
.env    GEMINI_MODEL=gemini-3.1-flash-lite
확인     화면 오른쪽 위 배지 · /actuator/health · 응답의 `model` 필드
```

실제로 겪은 차이다. 같은 입력인데 모델에 따라 재생성이 걸리기도 하고 안 걸리기도 했다.

```
gemini-3.5-flash-lite   4주 x 10h   재생성 걸림
gemini-3.1-flash-lite   4주 x 10h   한 번에 통과
```

그래서 어느 모델이 답했는지를 안 남기면 결과가 흔들려도 원인을 못 찾는다.

### 한도를 전제로 설계했다

호출 수가 병목이라 그에 맞춰 짰다.

```
강의 43개를 통째로 프롬프트에 넣는다      요청당 1회 호출. 검색 호출을 안 만든다
검증은 코드가 한다                       모델에게 되묻지 않는다
재생성은 최대 3회, 180초에서 끊는다        한 요청이 한도를 다 먹지 않게
```

RAG로 갔으면 임베딩 호출이 붙어 **요청당 2회**가 된다. 토큰이 아니라 **호출 수가 한도**라서
무료 구간에서는 오히려 손해다.

## 3. 왜 LangGraph인가, 뭘 막나

### 먼저 — 막는 것은 LangGraph가 아니라 검증 루프다

정확히 말하면 이렇다.

```
막는 것      verify (코드 검사) + 재생성 루프
LangGraph    그 루프를 표현하고 관측하는 방법
```

발표에서 이 순서로 말하는 게 정직하다. **"LangGraph를 썼더니 환각이 막혔다"가 아니다.**

### 루프가 실제로 막는 것

모델이 번호 목록을 준다. 그 번호가 틀릴 수 있다.

| 검사 | 안 막으면 사용자가 보는 것 |
|---|---|
| 존재하는 번호인가 | **없는 강의**가 로드맵에 뜬다 (환각) |
| 중복은 없나 | 같은 강의를 두 번 듣게 짜준다 |
| 예산을 넘지 않나 | **8주에 못 끝내는 계획**을 받는다 |
| 트랙 안에서 난이도가 순서대로인가 | 고급을 입문보다 먼저 들으라고 한다 |
| 형식이 맞나 | 서버가 500을 낸다 |

실제 실행 로그다. 시연에서도 이게 그대로 뜬다.

```
generate  시도 1
verify    실패 · 기간 초과: 65h > 40h
  ↺ generate 로 되돌아간다
generate  시도 2        ← 뭐가 틀렸는지 프롬프트에 붙여서 다시 부른다
verify    통과 · 40h
schedule  4주
```

**되돌아갈 때 백지에서 다시 짜지 않는다.** 실패 사유를 프롬프트에 붙인다.

```
문제: 기간 초과 65h > 40h
25시간을 줄여야 한다. 목표에서 먼 강의부터 뺀다. 강의 하나만 남아도 괜찮다.
목표 적합성은 유지한다. 관계없는 강의로 바꿔치지 않는다.
```

그래서 두 번째 시도가 첫 번째와 무관한 게 아니라 **깎아낸 버전**으로 온다.

### 그럼 for문으로도 되지 않나 — 된다

솔직한 답이다. 처음에는 실제로 `for` 문이었다. 옮긴 이유는 사이클 자체가 아니라 **트레이스에
뭐가 남느냐**다.

`for` 문에 데코레이터만 달면 이렇게 남는다.

```
build
  ├ generate  4.2s     ← 왜 3번인지 안 남는다
  ├ generate  3.8s
  └ generate  4.1s
```

실패 사유가 지역변수 안에 있어서 밖으로 안 나온다. 노드로 쪼개면 그게 그대로 올라간다.

```
generate  시도 1 · 토큰 2800
verify    실패: 기간 초과 65h > 40h     ← 이유가 남는다
generate  시도 2 · 토큰 5600
verify    통과
```

**"첫 시도 통과율"을 프롬프트 품질 지표로 쓰는데, 그 숫자가 대시보드에 보이려면 이 구조가
필요하다.** 지표로도 내보내고 있다.

```
첫 시도 통과율 = curriculum_roadmap_first_try_total / curriculum_roadmap_requests_total{outcome="ok"}
```

### 안 쓰는 기능도 밝힌다

LangGraph에는 더 있지만 여기서는 안 쓴다.

```
체크포인터    안 씀. 요청 하나 안에서 끝난다
interrupt     안 씀. 사람이 중간에 끼어들 지점이 없다
병렬 노드      안 씀. 호출이 직렬 1~3회
```

**강의 생성 중복 체크 기능을 하게 되면 그때 `interrupt`가 필요해진다** — 유사 강의를 보여주고
강사 판단을 기다렸다가 이어가는 흐름이라, 그게 원래 용도다.

## 나올 만한 질문

**"왜 RAG를 안 썼나"**
전체 강의 설명이 1,363자다. 검색할 문서가 없다. 통째로 넣는 게 더 정확하고 호출도 적다.

**"LangChain은 왜 안 썼나"**
LangGraph가 LangChain을 요구하지 않는다. 노드가 그냥 파이썬 함수다. LangChain이 주는 것
(모델 래퍼·프롬프트 템플릿·출력 파서)은 이미 더 싸게 있다 — Gemini가 `responseMimeType` 으로
JSON을 서버에서 보장한다. 넣으면 패키지 11개가 따라오고 `pydantic` 이 강제로 올라간다.

**"모델이 이상한 걸 고르면"**
계산으로 잡히는 것(없는 번호·중복·예산 초과·난이도 역전)은 코드가 잡고 되돌린다.
**"이 강의가 목표에 맞나"는 못 잡는다.** 그건 프롬프트로 유도하고 평가셋 8케이스로 확인한다.
실행 중에는 안 본다 — 확인하려면 LLM을 한 번 더 불러야 하는데 호출이 2배가 된다.

**"3번 다 실패하면"**
지금까지 고른 것을 검증 문제와 함께 내보낸다. 응답의 `problems` 에 사유가 실리고 화면에
빨간 박스로 뜬다. 아무것도 안 주는 것보다 낫다고 봤다.

**"유료로 가면 얼마나 드나"**
코드는 그대로다. 평가셋 8케이스 실측이 **입력 17,211 · 출력 2,795 토큰(호출 9회)** 이다.
호출당 입력 약 1,900토큰이고 출력은 고른 강의 수에 따라 40~600토큰으로 흔들린다.
입력이 큰 건 강의 43개를 매번 통째로 넣기 때문이고, 이건 캐싱으로 줄일 여지가 있다.
