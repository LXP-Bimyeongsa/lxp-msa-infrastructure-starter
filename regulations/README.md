# 규정 원본

조직 규정 QA 챗봇이 답변 근거로 삼는 원천 문서다. 여기를 고치면 재색인이 필요하다.

## 현재 상태

**실제 규정을 기다리는 중이다.** 초안으로 만들었던 임의 규정과 골든셋은 제거했다.
팀에서 실제 규정을 가져오면 아래 규약에 맞춰 이 폴더에 넣는다.

## 파일 구성

카테고리마다 파일 하나를 둔다. 파일명은 `NN-카테고리.md` 형식이다.

```
regulations/
  01-출결.md
  02-훈련장려금.md
  ...
  golden-set.yaml
```

## 조항 번호 체계

챗봇이 출처를 인용하려면 가리킬 주소가 있어야 한다. 조항 번호가 그 주소다.

```
제3장 출결
  제12조(지각의 기준)
```

인용은 `01-출결.md 제12조` 형태로 나간다.

**조항 번호는 재사용하지 않는다.** 조항을 삭제하면 번호를 비워두고 새 조항은 뒤에
붙인다. 번호를 돌려쓰면 과거 답변의 출처가 엉뚱한 곳을 가리킨다.

가져온 규정에 조항 번호가 없으면 인용 주소를 만들 방법을 먼저 정해야 한다. 설계에
영향을 준다.

## frontmatter

모든 파일이 아래 세 값을 갖는다. 색인할 때 청크마다 메타데이터로 붙는다.

```yaml
---
category: 출결
version: 1.0.0
effective_date: 2026-03-01
---
```

규정을 고치면 `version`을 올리고 `effective_date`를 갱신한다. 재색인이 이 값을 보고
갱신 대상을 판정한다.

## 표

조건부·계산형 질문은 표가 있어야 답이 나온다. "3일 결석하면 얼마 깎여요"에 답하려면
결석일수별 감액표가 문서에 있어야 한다.

**표는 청킹할 때 쪼개지 않는다.** 행이 잘리면 답이 틀린다.

## 골든 QA 셋

`golden-set.yaml`이 챗봇 평가 기준이다. 규정을 고치면 여기도 같이 고친다.

```yaml
answerable:
  - id: A-01
    q: "몇 분까지 봐주나요?"
    answer: "10분. 훈련 시작 시각으로부터 10분을 초과하면 지각이다."
    source: [01-출결.md#제12조]
    type: A          # A 단순 조회 · B 조건부·계산형

trap:
  - id: T-01
    q: "병가 내면 결석 처리되나요?"
    why: "출결 규정에 병가 조항이 없다"
```

### 측정

| 지표 | 방법 | 자동 |
|---|---|---|
| 출처 정확도 | 답변이 인용한 조항이 `source`와 일치하는가 | 가능 |
| 회피율 | `trap` 항목에 전부 거절이 나오는가 | 가능 |
| 정답률 | 생성 답이 `answer`와 맞는가 | judge 또는 사람 |

### 질문을 쓰는 요령

**규정 문구를 그대로 베끼지 않는다.** 실제 사용자가 쓸 법한 구어로 쓴다. 문구가
겹치면 검색이 쉬워져서 점수가 실력보다 높게 나온다.

```
규정   "훈련 시작 시각으로부터 10분을 초과하여 입실한 경우 지각으로 처리한다"
나쁨   "지각의 기준은 무엇인가요?"      문구가 겹쳐 그냥 걸린다
좋음   "몇 분까지 봐주나요?"            실제로 이렇게 묻는다
```

**함정 질문은 인접 주제로 만든다.** "점심 메뉴 추천해줘"는 너무 쉬워서 회피 능력을
재지 못한다. 출결 규정은 있는데 병가 조항만 없는 식이라야 실제 능력이 드러난다.

여러 조항을 함께 찾아야 답이 나오는 질문을 몇 개 넣으면 검색 품질이 드러난다.
훈련장려금 감액을 묻는데 출결의 환산 규칙까지 봐야 하는 경우가 그렇다.

### 비워둘 영역을 정한다

함정 질문을 만들려면 규정에 없는 영역이 필요하다. 어떤 주제를 다루지 않을지 정하고
여기에 적어둔다. **나중에 그 영역을 규정에 추가하면 함정 질문도 같이 고쳐야 한다.**
